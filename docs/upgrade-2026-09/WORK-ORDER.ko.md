# SIHOO DRAFT 테마 업그레이드 작업지시서

작성일: 2026-09-08. 기준 커밋: b479ce2. 대상 테마: `187727839523` (WORK - SIHOO Symmetry 2026-09 fixes DRAFT). LIVE `181013971235`는 게시 대상이 아니다.

## 목적과 작업 경계

관리자가 어느 템플릿을 편집하는지, 어떤 상품/페이지가 함께 바뀌는지 이해할 수 있는 구조를 만든다. 기존 관리자 편집과 리뷰 출처 안내 작업을 보존한다. 디자인 개선과 상품 사실 검증을 구분하고, 공개 테마 게시 및 상품/페이지 템플릿 재할당은 별도 변경으로 관리한다.

현재 템플릿은 165개, 섹션 140개, 스니펫 148개다. 상품 48개·페이지 56개·컬렉션 119개의 할당은 [연결 대장](TEMPLATE-MAP.ko.md)에 기록했다. 블로그/게시글·앱 내부 설정·URL view 지정은 추가 조사 대상이며 미할당 파일을 삭제하지 않는다.

## 확인된 충돌 위험

- M59 전용 `product.m59.json`이 원격에서 변경됐지만 M59 상품은 기본 `product`에 할당돼 있다. 이번 작업에서 해당 파일과 할당을 건드리지 않는다.
- 기본 상품 템플릿은 ACTIVE 5개 상품이 공유한다. 모델별 문구를 고정하지 않는다.
- `page.contact`는 공개 Contact와 Repair 두 페이지가 공유한다.
- `main-product`는 JSON 템플릿 31개에서 참조된다. 공통 섹션 코드는 영향 범위를 먼저 조사한다.
- `page.spring-sale` 지정에 대응하는 DRAFT 파일이 없다. `collection.B2Bspark`는 파일 이름 `b2bspark`와 대소문자가 다르다. 실제 렌더링 확인 후 처리한다.

## 구현 규칙

1. 기존 section type, setting id, block id를 유지한다. 이름만 정리해도 저장된 설정이 보존되도록 한다.
2. 새 전용 템플릿은 `page.sihoo-contact`처럼 목적을 명시한다. 모델별 값은 가능한 상품 데이터에서 읽고 레이아웃이 다를 때만 템플릿을 나눈다.
3. 새 커스텀 섹션 이름은 SIHOO로 시작하고 설정 설명에 공통/개별 영향 범위를 쓴다.
4. 테마 안에 관리자 확인 메모를 고객용 콘텐츠로 출력하지 않는다. 편집기 전용 안내는 `request.design_mode`로 제한한다.
5. 상품 데이터와 templateSuffix는 테마 전용 데이터가 아니다. 이번 단계에서 변경하지 않는다.
6. 업로드 직전에 대상 원격 파일을 다시 받아 기준선과 비교한다. 차이가 있으면 통합 후 다시 검수한다. 이는 원자적 편집 잠금이 아니므로 같은 파일 동시 편집을 피한다.
7. DRAFT ID와 `--only` 대상 파일, `--nodelete`를 명시해 업로드한다. 전체 업로드·자동 삭제·LIVE 게시를 수행하지 않는다.
8. 업로드 후 원격 파일 재수집으로 내용 일치를 확인하고 프리뷰로 렌더링을 확인한다. 정적 검사와 실제 화면 검증 결과를 구분한다.
9. 복원도 최신 원격과 충돌 확인 후 해당 파일만 복원한다. 다른 관리자가 그 후 추가한 변경을 덮어쓰지 않는다.

## U02 상세 지시

영향 템플릿: `product.m57`, `product.m-18`, `product.c300-pro-2`. 섹션 참조 기준이며 실제 할당은 연결 대장을 따른다.

- 편집기 이름을 `SIHOO Specs & fit guide`로 명확히 한다.
- 레이아웃 설정은 같은 템플릿 전체에, 상품 사양 값은 해당 상품의 LIVE/DRAFT에 영향을 준다는 안내를 넣는다.
- `heading`, `show_fit_guide` ID와 기본값은 유지한다.
- 표준 책상 높이에 무조건 적합하다는 문장을 제거한다.
- 사용자 키 양쪽 값이 있어야 범위를 출력한다. 좌판/전체 높이 최대값이 없으면 빈 범위를 출력하지 않는다.
- `needs_confirmation`이 남아 있으면 Fit guide를 숨기고 편집기에서만 확인 안내를 표시한다. 검토 메모를 고객에게 출력하지 않는다.
- 메모가 비었다는 사실을 제품 검증 완료로 간주하지 않는다. 기존 사양표 데이터의 정확성은 U05에서 증거로 확인한다.
